# Java 组：从零到国奖

8 节覆盖两条路：第一次参赛，和已经拿到省一冲国赛。

我打了两次这个比赛。第一次省二，第二次省一 + 国三。

中间那一年，我没多学多少语法。变的是四个判断。

## 一、最容易拿的分，排在最前面

省赛 4 小时，线上。从组委会的系统下载赛题文件，做完提交回系统，超时就提交不了。

文件里两块：**结果填空占 25%，编程大题占 75%**。官方公布的是这个比例；具体几道题、每题多少分，每年不一样。

这两块不是一个游戏：

- 填空不要求写程序。手算、用软件、甚至写代码都行，答案对就得分
- 编程只能老老实实写代码提交，而且是 IO 赛制——通过几组测试数据，给几分

所以那 25%，是最接近「想明白就能拿到」的地方。而它排在最前面。

如果一打开就冲编程，很可能写到最后一小时来不及，填空随便填两个数就提交。这部分分丢得最没道理。

## 二、官方文档几十页，真正考的是三个能力

1. 解决实际问题的能力，也就是业务理解
2. 算法与数据结构的灵活运用
3. 用 Java 把代码写出来的实现能力

前两项对所有语言组都一样，第三项才是分组的原因。

而第三项，是三个里最容易练、见效最快的。往这里投时间，比死磕算法划算。我自己当时的判断是：算法那一项，对拿到稍微好一点的奖，限制不大。

## 三、这套东西不教人变强，教人把分保住

我给它起的名字叫「输家思维」。

拿不到高分，往往不是不会，是把四小时花在了做不出来的题上。有效的是反过来：**先承认自己做不出最优解，再算清楚这种情况下最多能拿多少。**

动作很硬——一道题想了十几分钟没思路，立刻停手，用最笨的办法写一个能跑通部分数据的版本提交，马上换下一道。一次只拿一部分分，两三道加起来，比死磕一道题划算得多。

这套东西要成立，前提是你知道两件事：哪些题该放、放到什么程度。第 6 节整节在讲这个。

所以两套赛制的重心不一样：省赛考你能做出来多少，国赛考你做不出来的时候还能保住多少。同一套思路，两个赛制下的用法不一样。

## 四、我按决策顺序讲，不按官方文档的顺序

第一次备赛，我把官方文档从头读到尾。读完记住了一堆规则，但不知道该从哪件事开始。

官方文档是写给所有人的：参赛对象、赛制、机器环境、考察范围、奖项设置。它必须全覆盖，所以它不会告诉你哪件事该先做、哪件事其实可以不碰。

我把它重排成决策顺序：先判断值不值得打，再决定投多少时间，然后才是环境、真题、题型。每节结尾都有一个明确动作，不是一个知识点。

## 课程里还有什么

判断之后是执行。这部分我按能直接用的形状整理过：

- **4 小时时间轴**：精确到分钟，含「第几分钟还没思路就必须弃题」的判定线
- **提交前检查清单**：我比赛前一晚只看那张纸
- **输家思维的具体用法**：写不出最优解时，怎么用最笨的办法把该拿的分拿到
- **拿奖参照物**：什么水平大概对应哪个档，用来定目标，不是用来许愿
- **分题型拿分策略**：同一类题给一份打法，不给题解
- **近 7 万字 Java 基础笔记**：按考纲重排，卡住了能对着定位，不是教科书
- **环境包和提交流程截图**：环境装不上的人，第 3 节能直接照做

完整课程的入口，在仓库首页。

## 我踩过的坑

第一次省二。国赛目标定国二，最后国三。填空题拿过 0 分。

写这些不是自谦——是想说，上面那些判断是踩过之后留下的。
