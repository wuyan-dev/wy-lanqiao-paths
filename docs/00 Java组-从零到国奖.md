# Java 组：从零到国奖

你好，我是梧焰。我打了两次这个比赛，第一次省二，第二次省一 + 国三。中间那一年，我没多学多少语法。

这篇写给三种人：正准备第一次参赛、连 Java B 组考什么都不知道的；已经拿了省一、想在国赛再够一下的；还有打过一次、成绩不理想、想搞清楚问题出在哪的。这三段我自己都走过。

## 你可能正卡在这一步

官方文档几十页，参赛对象、赛制、机器环境、考察范围、奖项设置，一条不落。你从头读到尾，规则记住了一堆，合上页面还是不知道今晚该干什么。

于是你去搜。搜到的东西不少，Java 基础、算法、真题都有，但拼不成一条路——不知道先看哪个、哪个其实可以跳过。看完更慌了。

这不是你的问题。

因为**刚开始的时候，人最缺的从来不是知识点，是认知。**

认知之后是执行力，执行力之后才是对知识的理解和掌握。这个顺序搞反了，你就会一直在收集资料，一直不动手。

所以知识点我不做——有人比我讲得好。这门课做的是最前面那一层：把「这场比赛的准备到底在准备什么」讲清楚，再把认知拆成能做的动作。

下面三条，是那一年真正变了的东西。

## 一、先找到那个已经到过的人

**如果你想到达一个地方，最快的方式是找到一个已经到过那儿的人，看他是怎么到的。**

这是我做事的第一原则，我叫它「找对标」。

你还在迷迷糊糊、啥也不知道的时候，先照着他的做，至少一开始不会跑偏。这比你自己瞎摸快得多，也比你纠结「该先学什么」有用。

但也不要只找一个。

网上的经验太散。即使是一些获奖的人写的备赛过程，往往也不够全面——看完之后，脑袋里好像学到了什么，又好像还是不知道该怎么去做。

**我的做法是：找很多个，然后压成一套自己的流程。**

察觉自己的问题 → 抓住它，哪怕还很模糊 → 去找对标 → 把他的流程自己手打一遍 → 有点感觉了，再回头审视自己还缺什么 → 继续找 → 差不多了就开始干。

「自己手打一遍」这一步别省。看一遍和打一遍，是两件事。

代价也真实：为了做计划，你得先了解得足够多，计划才靠谱，但留给练习的时间就短了。这就是为什么我只拿到国三。所以**越早准备越好**。

## 二、官方文档不用从头读到尾

**官方文档每届都在重复同一批东西。用架构师的视角看，这叫构件复用。**

重复的那部分是地基，你只要盯住这届变了什么。

所以读官方文档不是从头读到尾，是先分清哪几块每届都一样、哪几块这次动了。一样的，做成模板提前备好；变的，留在场上填。

你先有这个认识，读起来就不会那么累——因为你知道自己在找什么，而不是在背一本规则手册。

这条两门课都适用。智能体开发那门，两届真题之间我也只找了变的那一小块。

## 三、不教人变强，教人保底

**这是整门课最要紧的一条。我叫它「输家思维」。**

拿不到分，往往不是不会，是把四小时花在了做不出来的题上。

反过来才对：先承认自己做不出最优解，再算清楚在这种情况下最多能拿多少。

具体动作很硬——一道题想了十五分钟没思路，立刻停手，用最笨的办法写一个能跑通部分数据的版本提交，马上换下一道。一次只拿一部分分，两三道加起来，比死磕一道题划算。

一句话：**按数据规模拿部分分。会正解写正解，不会正解写暴力循环骗分。**

你可能会说：这不就是骗分吗？

是的，但这是在规则内的骗分。测试数据分档，你写出能过第一档的代码，那一档的分就是你的。放弃它才是白丢。

省赛和国赛的重心也不一样：省赛考你能做出来多少，国赛考你做不出来的时候还能保住多少。同一套思路，用法不同。

## 课程里还有这些

认知之后是执行。这些是我按「能直接照着做」的形状整理出来的：

- **4 小时时间轴**：精确到分钟，含「第几分钟还没思路就必须弃题」的判定线，让你在比赛时不用再想时间怎么分
- **提交前检查清单**：我比赛前一晚只看那张纸，过一遍就不会因为格式问题白丢分
- **我实际找过的对标**：找过哪些人、从每个人身上具体拿走哪一条，省掉你自己筛选的时间
- **拿奖参照物**：什么水平大概对应哪个档，用来定目标，不是用来许愿
- **近 7 万字 Java 基础笔记**：按考纲重排，不是教科书，是卡住时能查的索引
- **环境包和提交流程截图**：环境装不上的人，第 3 节能直接照着做

完整课程的入口，在仓库首页。
