##### 1）鲁棒性测试

**第一：鲁棒性测试**。我们在测试的时候，**尽可能的让它处理问题的能力更强**。

**第二，工程效率**。我们不用去看它那个计算分，**只要自己抓住了核心原理**，不用管那个，那个只会把我们整懵圈了。

**核心就是两个（上面有提到过）：**

1、**消耗的 Token 数**

2、**运行时间长短**

**记住，就这两个核心**。我们要做的就是**让消耗的 Token 数尽可能的少**，**运行时间尽可能的短**，那么如果我们的分数到了 30 分，它自动会计算的。**所以我们专注于把自己的习惯给做到尽可能的专业**，**尽可能的好**，**专注于技术，那些了解即可**。

<callout emoji="🥠">
**预告一下，**运行时间上有一个技巧，叫做**把无前后依赖的执行路径从串行模式变为并行模式**。这就是核心。抓住这个基本上就够打比赛了。后面会讲。
</callout>

>

###### 所以，我们使用哪个节点呢？

**按照现在的情况再做一次清晰的分析：**

同样的操作，可以选的节点有：循环节点 和 并行执行 节点。

那操作之间有没有依赖关系，决定了使用哪个节点。串行的是 循环节点；并行的是并行执行节点。

**对照我们的情况：同样一个操作，操作之间没有依赖关系**，**所以选择并行执行节点**。

<callout emoji="📖">
**补充知识：**
在工作流中，用**并行模式**处理同一任务和加入**循环节点**，核心区别在于**执行顺序、任务间的依赖关系以及结果聚合方式**。
简单来说：**并行模式是“同时分头做，做完再汇总”，适合互不依赖的重复任务；循环节点是“排着队一个一个做”，适合需要顺序处理或前后有依赖的场景。**
### 核心区别对比
**执行方式与效率**
- **并行模式**：多个任务**同时**启动、并发执行，总耗时通常更短，适合追求吞吐量的场景。
- **循环节点**：默认**顺序**执行，一轮结束后再开始下一轮，总耗时较长，但资源占用更稳定。
**任务间依赖与数据访问**
- **并行模式**：各分支相互**独立**，通常无法直接读取彼此中间产生的变量，只有等全部汇合后，下游才能拿到汇总结果。
- **循环节点**：每一轮可以**依赖**上一轮的结果或更新的全局变量，适合需要“基于上一步结果调整下一步”的迭代优化。
**结果输出与聚合**
- **并行模式**：通常自动收集所有并发任务的结果，并保持与输入顺序一致，输出一个结果数组。
- **循环节点**：默认往往只输出**最后一轮**的结果。若要收集每一轮的数据，通常需要手动配合“全局变量”或“变量更新”节点来累加。
**适用场景**
- **并行模式**：处理一批**互不相关**的独立数据（如同时翻译100条独立短句、同时调用多个不相关的API）。
- **循环节点**：处理**有顺序要求**或**需要迭代**的任务（如逐段生成文章且后文需参考前文、反复修改直到评分达标、需要用户在过程中填表的交互任务）。
</callout>

#### 4、修改主键与新增字段

##### 1）思路分析

主键只能修改，不能添加也不能删除。其他字段我们直接新增。所以这里的任务为两条线，一条修改主键，一条新增字段。

**但是一个很重要的问题：该如何和前面的连接起来**。**这里，用到一个新的节点——判断器 节点**。

**具体思路是这样的：**

1、把前面三个分支的尾巴连接上 判断器 节点的头；

##### 1）拆解计分原理

这里的计分规则我是这样设计的：

**模型输出计分要素：**它把这条点评拆成若干条，每条只有两个方面——标签（在说哪一方面）、方向（1 夸、-1 骂、0 陈述）。

**代码分两堆：**

> good = [口味绝佳, 性价比高]     ← 夸的方面
>
> bad  = []                      ← 骂的方面

都是数组形式。

同一方面重复出现只记一次。接着比较这两个名单的长度，判断顺序如下：

> ① good ≥ 3 且 bad = 0   → 5 星
>
> ② bad  ≥ 3 且 good = 0  → 1 星
>
> ③ good > bad            → 4 星
>
> ④ bad  > good           → 2 星
>
> ⑤ 剩下（相等，或两边都空） → 3 星

获取到要素之后，我们就写代码完成上述功能，即编程。

##### JSON 语法规则

<callout emoji="🐱">
这是一个非常典型的 “变量类型”与“JSON 语法” 混淆的问题。
**节点输出是 `String` 类型，并不代表它插入到 JSON 文本中时，会自动带上双引号。** **如果它要的是 `String`，必须手动给它加上双引号**。
### 为什么必须要加双引号？
JSON 要的是一种**文本格式**（纯字符串）。当在请求体（Body）里写代码时，是在“拼凑”一段符合 JSON 语法的纯文本。
在 JSON 语法规则中：【**主要看这里：这个很全了**】**🌟🌟🌟🌟🌟**
1. **字符串（String）** 的值，**必须被双引号包裹**。例如：`"sentiment": "好评"`
2. **数字（Number）** 的值，**不加引号**。例如：`"rating": 5`
3. **布尔值（Boolean）**，**不加引号**。例如：`"is_vip": true`
4. **数组（Array）** 或 **对象（Object）**，**用 `[]` 或 `{}` 包裹**。例如：`"tags": ["好吃", "便宜"]`
请求体在当前节点被**当成一段纯文本发送**，平台在发送前做了一件事：**把 `{{变量}}` 替换成变量的真实值。**
