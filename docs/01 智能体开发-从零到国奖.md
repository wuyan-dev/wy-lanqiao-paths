# 智能体开发：从零到国奖

你好，我是梧焰。

这个赛项第十六届才设立，也就是第一届。能参考的真题只有十七届、十八届两届，我都跑过一遍。

第一次我连该准备什么都不知道，四小时下来什么都没捞到。第二次：省一 + 国三。

这篇写给三种人：第一次听说这个赛项、不知道它是干什么的；已经在软件赛拿了省一、想再开一条赛道的；还有上一次四小时没做完、想搞清楚问题出在哪的。

## 你可能正卡在这一步

建应用、拖节点、连线，这些很快就能学会。

可一拿到赛题，还是会卡住：这个业务该拆成几个环节？异常该走哪条分支？字段该怎么定？

这时候你会发现，**拖节点是整件事里最不值钱的部分。**

四小时不够用，我复盘下来是三个原因：

1. **熟练度不够**——每一步即使会，都要想一下，十步下来时间就没了
2. **理解程度不够**——不知道该用哪个节点、哪个参数，卡在那里试
3. **业务场景处理能力不够**——不知道这个业务该怎么拆

第三条最要命，也最难自学。

## 一、这个赛项不考题库

软件赛办了十几届，题库厚得能刷一年。这个赛项没有这个条件，能参考的只有两届真题。

所以软件赛那套「靠刷题量堆上去」的办法，在这里不成立。

那靠什么？靠**构件复用**。

**官方文档每届都在重复同一批东西。用架构师的视角看，重复的部分是地基，你只要盯住这届变了什么。**

我把四份真题并排看过——十七届样题、十七届省赛、十七届国赛、十八届样题——骨架是同一套 9 段：赛题背景、任务目标、功能要求、技术实现要点、提交要求、评分标准、附件、绝对禁令红线、常见问题。

变的是其中某几段的内容，不变的是结构。

所以十八届不是从零重做，是拿十七届的东西替换。这也是为什么我看官方文档的方式是：**每届都一样的，做成模板提前备好；每届会变的，留在场上填。**

按这个分法，场上真正要现做的只有一小块，剩下的都是搬。

## 二、省赛靠复用，国赛靠创造

这句话是我复盘两届之后才想明白的。

**省赛之前，把这套逻辑练熟，基本就够了。但国赛之后，考的是真正的能力——不能再依靠原来的逻辑，要自己根据赛题造一套属于你的逻辑。**

注意，是「在原来的地基上造」，不是推倒重来。地基还是那些构件。

所以准备国赛的重点不是把这些再练一遍，是练「拿到一个新业务，怎么快速拆出流程、定出字段」。

## 三、做得出来不等于分高

这一项总分 110，构成是这样的：

核心功能 55、工作流与 Prompt 20、工程效率 15、文档与交付物 10、创新性 10。

**一半以上的分，不在「你把功能做出来」这件事上。**

文档那 10 分，最容易被放到最后 20 分钟赶，赶出来的东西过不了「内容详实」那一关；工程效率那 15 分，靠的是提前备好能复用的构件，不是现场重新搭。

这两块都是可以提前备的，不是靠临场发挥。

还有一条不能忘：二机位监控，四小时，提交物少交一件、字段名或字段顺序不对，对应项直接不得分。红线那几条，一条都不能碰。

我第二次把 `score` 写成 `socre`，报 `NameError`，卡了很久。这种错不是不会做，是没检查。

## 7 节，每节给你什么

| 节 | 你能拿到什么 |
|---|---|
| 0 | 知道这个赛项是什么、评分怎么给、当天要交什么，心里先有底 |
| 1 | 判断值不值得打，知道奖项比例和报名时间，不错过截止 |
| 2 | 看懂四小时赛制、机器环境、110 分怎么拆，以及那三条不能碰的红线 |
| 3 | 跟着十七届样题走完整流程：从建飞书应用到提交，一处不卡 |
| 4 | 拿十七届的智能体改造成十八届，看清两届之间到底只变了哪一块 |
| 5 | 四份真题并排，拆出固定的 9 段结构，下次拿到新题不再慌 |
| 6 | 三个准备方向的具体练法：熟练度、理解程度、业务场景处理能力 |

## 课程里还有这些

- **十七届样题完整实操**：16 万字。从进飞书开放平台建企业自建应用、拿 App ID 和 Secret、开通权限，到每个节点的配置、每个报错怎么解决，全过程都有记录
- **十八届改造全过程**：5.5 万字。全局变量、开场白、新增字段、反馈节点，一处一处对着改
- **技术说明文档模板**：那 10 分不用自己从零想结构
- **提示词模板 + JSON 语法速查 + 常用代码**：比赛时直接取用，不用现查
- **9 段赛题结构拆解**：四份真题逐段对照，哪段是干扰、哪段必须看
- **模版化开发的思路**：两届之间真正能复用的到底是什么

完整课程的入口，在仓库首页。
